GetX is a powerful, lightweight framework for Flutter that handles state management, dependency injection, and route management with minimal boilerplate code.

The pubspec.yaml file is the manifest for your Flutter project. It's the central configuration file that defines the project's metadata and dependencies.

Key Sections

  • name, description, version: Basic project metadata.
  • environment: Specifies the compatible Dart SDK version.
  • dependencies: Lists external packages your app needs to run (e.g., get, http).
  • dev_dependencies: Lists packages only needed for development and testing (e.g., flutter_lints).
  • flutter: Contains Flutter-specific configurations, like declaring assets (images, fonts).

The lib (short for library) folder is the heart of your Flutter project. It's where all your Dart code for the application lives.

Key Files & Folders

  • main.dart: The entry point of your application. Execution starts here.
  • Sub-folders (e.g., screens, models): Used to organize your code by feature or type, making the project maintainable.

Serialization is the process of converting a complex data object (like our `Habit` class instance) into a format that can be easily stored or transmitted, and then reconstructed later. The most common format for this is JSON.

The BuildContext is a locator that is used to handle a widget's location in the widget tree. Each widget has its own `BuildContext`, which becomes the parent of the widget returned by the `build` function. Essentially, it tells a widget *where* it is among all the other widgets.

A class is a blueprint for creating objects. It bundles data (properties) and functions (methods) that operate on that data into a single, reusable unit.

The final keyword declares a variable that can only be assigned a value once. It must be initialized either when it's declared or in the class constructor. Use it to create immutable properties.

The toJson() method is a convention used in Dart for serialization. Its job is to convert an instance of a class into a `Map`, which is a structure that can be easily encoded into a JSON string.

A fromJson() factory constructor is the reverse of `toJson()`. It takes a `Map` (decoded from JSON) and uses it to construct a new instance of the class, populating its properties with the map's values.

A Map is a collection of key-value pairs. Each key in a map must be unique. It's Dart's equivalent of a dictionary or hash table in other languages, and it's the perfect structure for representing JSON data.

A factory constructor is a special type of constructor that gives you more control over the object creation process. Unlike a normal constructor, a factory constructor does not always create a new instance of its class. This is why we use it for `fromJson`, as it allows us to parse a map and return a fully-formed `Habit` object.

`async` and `await` are keywords that handle asynchronous operations in Dart. An `async` function returns a `Future`, and `await` pauses execution until that `Future` completes. We use this in `main()` to ensure `GetStorage` is fully initialized before the app runs.

The `any()` method is a powerful function available on all Lists in Dart. It checks if at least one element in the collection satisfies a given condition and returns `true` or `false`.

A `DateTime` object contains time down to the microsecond. To check if two `DateTime` objects fall on the same calendar day, you must compare their year, month, and day properties individually.

ISO 8601 is an international standard for representing dates and times as strings (e.g., `"2025-07-15T10:30:00.000"`). Dart's `toIso8601String()` and `DateTime.parse()` methods make saving and loading dates reliable.

The `DateTime.parse()` method is a constructor that creates a `DateTime` object by parsing a string that is formatted according to the ISO 8601 standard. It's the essential counterpart to `toIso8601String()`.

A StatelessWidget is a widget that describes a part of the user interface which cannot change its own state once built. Its appearance is determined solely by the configuration passed into it from its parent.

`super.key` is a modern Dart feature that forwards a widget's `Key` to its parent class constructor (`super`). A Key is an object used by Flutter's engine to identify and differentiate widgets, which is crucial for performance and state preservation in lists.

A Scaffold implements the basic Material Design visual layout structure. It provides a framework for adding common UI elements.

Key Parameters

  • appBar: The horizontal bar displayed at the top of the screen.
  • body: The primary content of the scaffold.
  • floatingActionButton: A button that "floats" over the body.

The appBar parameter takes an `AppBar` widget (or a similar preferred app bar widget) to display as a persistent header at the top of the `Scaffold`.

The body parameter is where the main content of your screen goes. It accepts a single widget, which is often a layout widget like `Column`, `ListView`, or `Container` to hold other widgets.

The floatingActionButton parameter takes a `FloatingActionButton` widget that is layered on top of the `body`, usually in the bottom-right corner.

An AppBar is the toolbar that appears at the top of a screen, typically within a Scaffold. It's used for branding, screen titles, and actions.

Key Parameters

  • title: The main widget displayed in the app bar, usually a `Text` widget.
  • actions: A list of widgets to display after the title (e.g., icon buttons).

The title parameter accepts any widget, but is most commonly a `Text` widget that describes the current screen.

A ListView is a core widget that arranges its children sequentially in a scrollable list.

Constructors & Parameters

For a small, fixed number of items, use the default constructor:

  • children: A `List` containing all the items to display.

For long or dynamic lists, use ListView.builder:

  • itemCount: An integer specifying how many items are in the list.
  • itemBuilder: A function that is called to build each list item on demand.

The itemCount parameter tells the `ListView.builder` the total number of items in your list. The builder will then only call `itemBuilder` for indices from 0 up to `itemCount - 1`.

The itemBuilder is a function that Flutter calls whenever it needs to display a new item on the screen. It provides the current `BuildContext` and the item's `index`. Your function's job is to return the widget for that specific index. This is extremely memory-efficient.

A ListTile is a convenient, pre-styled Material Design widget that creates a fixed-height row. It's perfectly designed for use in lists.

Key Parameters

  • leading: A widget to display before the title.
  • title: The primary content, typically a `Text` widget.
  • trailing: A widget to display after the title.
  • onTap: A function to call when the tile is tapped.

The leading property places a widget at the very beginning of the `ListTile` row. It's often used for an `Icon`, `Checkbox`, or `CircleAvatar`.

The title is the main content of the `ListTile`. Although it can be any widget, it's almost always a `Text` widget.

The trailing property places a widget at the end of the `ListTile` row, after the `title`. It's commonly used for an arrow `Icon` or a `Switch`.

A Checkbox is a simple Material Design widget that allows the user to make a binary choice (true/false).

Key Parameters

  • value: A boolean (true/false) that determines if the box is checked.
  • onChanged: A callback function that is triggered with the new value when the user taps the checkbox.

The value must be a boolean. If `true`, the checkbox is displayed as checked. If `false`, it's displayed as unchecked.

The Column widget is a layout widget that arranges its children in a vertical array.

Key Parameter

  • children: A `List` containing all the widgets to be arranged vertically.

The Padding widget adds space around its child widget.

Key Parameters

  • padding: An `EdgeInsets` value that defines the amount of space.
  • child: The single widget to which the padding will be applied.

The padding parameter requires an `EdgeInsets` object. Common constructors are `EdgeInsets.all(8.0)` for equal padding on all sides, or `EdgeInsets.symmetric(horizontal: 16.0)` for horizontal padding only.

A SizedBox is a simple but highly efficient widget whose only purpose is to create a box with a specified size. It's most commonly used to create fixed-size gaps between other widgets.

Key Parameters

  • height: Creates vertical space.
  • width: Creates horizontal space.

An ElevatedButton is a Material Design button that appears "elevated" with a shadow. It's typically used for high-priority actions.

Key Parameters

  • onPressed: The function to execute when the button is tapped. The button is disabled if this is `null`.
  • child: The widget to display inside the button, usually a `Text` or `Icon`.

A FloatingActionButton (FAB) is a circular icon button that "floats" above the UI, typically in the bottom-right corner. It's used for a primary, promoted action.

Key Parameters

  • onPressed: The function to execute when the button is tapped.
  • child: The widget to display inside the button, which must be an `Icon`.

A TextField is a fundamental widget that allows users to enter text via a keyboard.

Key Parameters

  • controller: A `TextEditingController` to manage the text.
  • decoration: An `InputDecoration` to style the text field with labels, hints, and borders.

The controller parameter takes a `TextEditingController` instance. This object lets you read the text the user has entered (`controller.text`), set the text programmatically, and listen for changes.

The decoration parameter takes an `InputDecoration` object. This is where you configure the visual appearance of the `TextField`, such as setting the `labelText`, `hintText`, borders, and icons.

A TextEditingController is an object used to manage the text of a `TextField`. You must create an instance of it and attach it to a `TextField`'s `controller` parameter to be able to read or modify the text.

Properties like onPressed, onTap, and onChanged are all "callbacks". They are parameters that expect a `Function`. You provide the block of code that should be executed when the user interacts with the widget (e.g., taps a button). If you pass `null` to `onPressed`, the button will be automatically disabled.

The child parameter is used by widgets that can only contain a single inner widget (like `Padding`, `Container`, or `ElevatedButton`). You provide the one widget that will be placed inside it.

The children parameter is used by layout widgets that can contain multiple inner widgets in a specific arrangement (like `Column`, `Row`, or `ListView`). It always takes a `List` of widgets, written as `[ WidgetOne(), WidgetTwo(), ]`.

GetMaterialApp is GetX's replacement for Flutter's standard MaterialApp. It acts as the root of your application, enabling all of GetX's powerful features for routing, state, and dependency management.

ThemeData is a class that holds the color and typography values for a theme. Defining a `ThemeData` at the top of your app ensures all child widgets inherit the same visual styling for a consistent look and feel.

A GetxController is a class from GetX designed to separate your business logic and state variables from your UI code, promoting a clean architecture. It provides lifecycle methods like `onInit()` for setup and `onClose()` for cleanup.

`onInit()` is a lifecycle method provided by `GetxController`. It is called automatically by GetX right after the controller is allocated in memory. It's the perfect place to perform setup logic, like fetching initial data from storage or an API.

Get.put() is GetX's primary dependency injection method. It creates an instance of a controller (like `HabitController`) and registers it with GetX, making it available to all child widgets in the widget tree.

Get.find() is the GetX method used to find an already-created instance of a controller that was previously registered with `Get.put()`. It allows any widget to get access to the same controller instance without needing it to be passed down manually.

The .obs is a GetX extension that turns any variable into a "reactive" or "observable" stream. When an .obs variable's value changes, any reactive widget (like Obx) that uses it will automatically rebuild.

Obx is a GetX reactive widget that takes a function returning a widget. It automatically subscribes to any .obs variables used within that function. Whenever one of those variables changes, Obx efficiently rebuilds only itself, not the whole screen.

The `refresh()` method manually forces a reactive variable in GetX to update and notify its listeners. This is necessary when you change a property *inside* an object within a reactive list, as GetX can't automatically detect those deep changes.

The ever worker is a feature of GetX that listens to a reactive variable and executes a callback function every time that variable's value changes. This is perfect for auto-saving data whenever a list is modified.

Get.to() is GetX's primary method for navigation. It pushes a new screen onto the navigation stack. It's simpler than Flutter's native `Navigator.push()` because it doesn't require the `BuildContext`.

Get.back() is the GetX method for closing the current screen and "popping" it off the navigation stack, returning the user to the previous screen. It's the counterpart to Get.to().

GetStorage is a fast, extra-light, and synchronous key-value storage library. After initialization with `await GetStorage.init()`, you can read and write data instantly with `box.read(key)` and `box.write(key, value)`.
